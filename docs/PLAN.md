# AI Agent 기획서 — 제주 데이터 길잡이 (Jeju Data Navigator)

**「제주 AI·빅데이터 활용 AI Agent 개발 챌린지」 제출용 기획서 (초안 v0.1, 15쪽 이내)**

---

## 1. 구현 목표

### 1.1 분석 주제
**"읍면동 생활권 진단: 우리 동네에는 언제, 누가, 왜 모이는가"**
제주데이터허브의 **읍면동 단위 내국인 유동인구(No.753)** 를 필수 데이터로 삼고, 카드 소비(No.741)·버스 정류소 이용(No.725/726)·일별 기상(No.756)·음식점 인허가(No.571) 데이터를 결합해 소상공인·예비창업자·마을 활동가가 묻는 생활권 질문에 데이터로 답한다. 같은 엔진이 관광(No.755/746)·농업(No.5) 질문도 처리한다.

### 1.2 AI 를 활용한 데이터 분석 목표
1. **탐색 자동화** — 자연어 질문을 데이터 목록 1,259종과 대조해 적합한 데이터를 추천한다.
2. **수집·전처리 자동화** — Open API 페이지 수집, 파일 인코딩 판별, 컬럼 정규화, 구조 요약을 사람 개입 없이 수행한다.
3. **분석·시각화 자율 수행** — LLM 이 분석 계획을 세우고 pandas 코드를 작성·실행·수정하며 차트를 만든다.
4. **신뢰할 수 있는 결과 제공** — 모든 수치의 근거(코드·데이터 출처·기간·한계)를 보고서에 자동 첨부해 재현 가능하게 한다.
5. **비전문가 사용성** — 센터 PC 에서 더블클릭 → 질문 입력만으로 끝나는 서비스.

### 1.3 왜 이 주제인가
- 허브에서 가장 많이 즐겨찾기된 데이터가 유동인구(520)·카드(464)·버스(234)·음식점(234)으로, 도민 수요가 집중된 영역이다.
- 허브가 매쉬업 주제(예비창업자 업종별 매출, 상권분석 유동인구×카드)를 제공할 만큼 수요는 검증됐지만, 결과가 고정 보고서여서 "우리 동네, 이번 달" 질문에는 답하지 못한다. 에이전트는 이를 **질문 시점에 즉석으로** 수행한다.
- 유동인구·버스·기상·농산물 데이터는 일 단위 자동 갱신 Open API 라서 에이전트가 늘 최신 데이터를 다룰 수 있다.

## 2. 서비스 제안

### 2.1 데이터 활용 개요
| 단계 | 사용 데이터 | 방법 |
|---|---|---|
| 탐색 | 데이터 목록 1,259종 (챌린지 제공 xlsx) | 동의어 사전 + 글자 바이그램 유사도 + 인기도 점수화 |
| 수집 | 등록 데이터셋 14종 (Open API/파일/샘플) + 사용자가 내려받은 임의 파일 | 레지스트리(YAML) 기반 자동 적재·캐시, `load_file` 스키마 자동 추정 |
| 분석 | 유동인구(핵심) + 보조 4종 | 요일·월·연령대·성별 집계, 기상·버스·인허가·카드 결합 |
| 보고 | 전체 | 결론·근거·출처·한계·코드 자동 첨부 |

### 2.2 핵심 기능
1. **대화형 분석**: "애월읍은 주말에 사람이 더 많아?" → 데이터 선택·집계·차트·결론을 한 번에.
2. **결합 분석**: "비 오는 날 버스 손님은?" → 기상(관측소)과 정류소 승차를 날짜로 결합, 강수 구간별 비교.
3. **창업 상권 진단**: 거주·근무·방문 인구 구성 + 동종 업소 수·폐업률·영업 기간 + 소비 연령대.
4. **보고서 자동 생성**: HTML(대화형 차트)·Markdown·재현 스크립트.
5. **어떤 데이터든 분석**: 등록되지 않은 데이터는 허브에서 내려받아 `data/raw` 에 넣기만 하면 `load_file` 로 분석(목록 1,259종 전체 활용 가능). 없으면 데이터명·No.와 확보 방법을 안내.
6. **위치 분석**: 와이파이 AP·전기차 충전소·관광 숙박업·버스 정류소 좌표로 지도 차트.

### 2.3 편의성
- 설치 1회(`pip install -r requirements.txt`), 실행 1줄(`streamlit run app.py`), 예시 질문 버튼, 분석 과정 펼쳐보기, 판단 과정 요약, 내려받기 버튼.
- 전문용어 없는 답변 형식(결론→근거→출처→주의→다음 질문)을 시스템 프롬프트로 강제.
- 키·데이터가 없어도 합성 샘플로 전 과정 시연 가능(경고 표시).

### 2.4 분석 데이터 활용 방안
- 소상공인·예비창업자: 입지 후보 읍면동 비교, 요일·시간 운영 전략, 경쟁 업소 생존 기간.
- 마을·행정: 행사·장날 수요 예측 근거, 버스 노선·정류소 개선 근거, 우천 시 대응.
- 농가: 품목·등급별 출하 시기 가격 비교.
- 센터: 도민 질문 로그로 데이터 개방 우선순위 도출.

## 3. Agent 개발 구성

### 3.1 역할·목표·워크플로
단일 오케스트레이터 에이전트(Claude)가 6개 도구를 호출하며 다음 워크플로를 자율 수행한다.

```
질문 이해 → (필요 시) search_catalog → load_dataset → 구조 확인 → run_python(집계/결합) ⟲ 오류 수정
        → make_chart → 답변 작성 → (3단계 이상 또는 요청 시) write_report
```
- 모델은 각 단계에서 "무엇을 왜 하는지"(purpose)를 남기고, UI 는 이를 단계 카드로 보여준다.
- 도구 결과는 모델에게만 돌아가고, 사용자는 결론·차트·보고서를 본다.

### 3.2 사용 모델
- **Anthropic Claude `claude-opus-5-5`** (기본, `.env` 로 변경 가능). 적응형 사고(adaptive thinking) + 노력 수준 `medium`(비용·속도 균형, 필요 시 `high`).
- 프롬프트 캐시(고정 시스템 프롬프트·도구 정의)로 반복 호출 비용 절감, 스트리밍으로 응답 지연 체감 최소화, 서버측 fallbacks 로 안전 분류기 거절 시 대체 모델이 이어받음.

### 3.3 Tool / API
| 도구 | 역할 | 구현 |
|---|---|---|
| `search_catalog` | 데이터 목록 검색 | pandas + 동의어 사전(70여 개 생활 어휘) |
| `list_datasets` | 등록 데이터·세션 표 현황 | 레지스트리 YAML |
| `load_dataset` | API/파일/샘플 적재 + 정규화 + 요약 | `requests` Open API 클라이언트(페이지·캐시·오류), CSV/XLSX 로더 |
| `load_file` | data/raw 의 임의 파일 적재 | 인코딩·제목 행·시트 처리, 숫자/날짜 자동 추정, 경로 제한 |
| `run_python` | pandas 코드 격리 실행 | `python -I` 하위 프로세스, 모듈 허용목록, 시간·메모리·파일 경로 제한 |
| `make_chart` | 11종 차트 | plotly, 검증된 범주 팔레트, 집계·상위 N·정렬 |
| `write_report` | MD/HTML 보고서 | 출처표·코드·재현 스크립트 자동 첨부 |

외부 API: Anthropic Messages API(도구 호출·스트리밍), 제주데이터허브 Open API(`/api/proxy/{API ID}/{프로젝트 키}`).

### 3.4 판단 및 자율 수행 범위
| 구분 | 내용 |
|---|---|
| 스스로 결정 | 데이터 선택, 기간 기본값, 집계 방법, 결합 키, 차트 종류, 보고서 작성 여부, 오류 수정 |
| 사용자 확인 | 결과가 크게 갈리는 해석(지역 범위·비교 기준), 대량 수집, 미등록 데이터 확보 |
| 금지 | 수치 지어내기, 샘플을 실제처럼 설명, 도구 밖 통계 주장, 개인정보 취급, 외부 데이터 수집, 파일 삭제 |
| 상한 | 턴당 도구 호출 25회, 코드 실행 90초, 같은 오류 3회 반복 금지 |

## 4. 데이터 활용 계획

### 4.1 필수 데이터
| 데이터명 | 출처 | 활용 항목 | 수집·전처리 | 이용조건 |
|---|---|---|---|---|
| 읍면동 단위 내국인 유동인구 (No.753) | 제주데이터허브 Open API (일 갱신) | 날짜, 시군구, 읍면동, 성별, 연령대, 거주·근무·방문 인구 | 기간 지정 수집 → 날짜 파싱 → 요일/월 파생 → 읍면동·연령대·성별 집계 | 허브 이용약관, 출처 표시 |

### 4.2 보조 데이터 (13종) 및 임의 파일
일일 정류소별 버스 이용자(No.725), 버스 정류소 기본정보(No.726), 일별 기상(No.756), 내국인 관광객 카드 이용(No.741), 음식점 목록(No.571, 파일), 방문목적별 입도객(No.755), 관광지별 내국인 유입자(No.746), 농산물 품종별 일일 거래 통계(No.5), 공공와이파이 AP(No.720), 전기자동차 충전소(No.494), 관광 숙박업(No.518), 외국인 장기·단기체류 유동인구(No.747/748). 그 밖의 데이터는 사용자가 내려받아 `data/raw` 에 넣으면 즉시 분석 가능. 상세는 `docs/DATA_SPEC.md`.

### 4.3 수집·전처리 방법
1. Open API: 프로젝트 키 + API ID 로 페이지(number/limit) 반복 수집, JSON 의 데이터 목록·전체 건수 관대 파싱, 디스크 캐시, 인증·주소·형식 오류를 한국어 메시지로 변환.
2. 파일: `data/raw/` 글롭 패턴 자동 인식, 인코딩(utf-8-sig/cp949/euc-kr) 판별, 다중 파일 병합.
3. 정규화: 컬럼 공백 제거, 영문 키→한글명 rename, 날짜(YYYYMMDD 포함)·숫자(쉼표) 변환.
4. 요약: 크기·컬럼 형식·결측·예시값·미리보기를 모델에 전달해 "추측으로 컬럼명 쓰기"를 방지.
5. 샘플: 실제 데이터가 없을 때 레지스트리 구조를 따르는 합성 데이터로 동작, 경고 강제.

### 4.4 이용조건·윤리
출처 표시(보고서 자동 첨부), 키는 `.env` 에만 보관·로그 마스킹, 개인 식별 정보 미취급, 센터 비공개 데이터 외부 반출 없음.

### 5.2 기술 환경
Python 3.10+, Anthropic SDK 2.x, pandas 3, plotly 7, Streamlit 1.4x+, Windows/macOS/Linux. GPU 불필요.
