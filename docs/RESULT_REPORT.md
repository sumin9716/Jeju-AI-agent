# 결과 설명자료 — 제주 데이터 길잡이

> 최종 제출용 결과 설명자료의 골격입니다. "실행 결과" 절은 실제 데이터(Open API/원본 파일)로 시나리오를 실행한 뒤 수치·차트·보고서 파일로 채웁니다. (현재 저장소에는 합성 샘플 기반 시연 결과만 포함)

## 1. 문제 정의
- 제주데이터허브에는 1,259종의 데이터가 공개되어 있지만, 도민이 "우리 동네 질문"에 답을 얻으려면 데이터를 찾고(탐색), 내려받고, 전처리·분석·시각화하는 전문 작업이 필요하다.
- 제주빅데이터센터 방문자(소상공인·예비창업자·농어민·마을 활동가·공무원)가 **질문 한 번으로** 데이터 탐색부터 결과 보고서까지 받을 수 있는 AI Agent 가 필요하다.
- 대표 분석 주제: **읍면동 생활권 진단** — 유동인구(필수 데이터 No.753)·카드소비·버스·기상·인허가 데이터를 결합해 "언제, 어디에, 누가 모이는가"를 답한다. 같은 엔진으로 관광·교통·농업 질문에도 답한다.

## 2. Agent 구조
```
사용자(Streamlit/CLI) ──질문──▶ Agent 루프 (Claude claude-opus-5-5, adaptive thinking, effort=medium)
                                   │  tool_use ↔ tool_result 반복 (최대 25단계)
                                   ▼
      ┌──────────────┬──────────────┬──────────────┬──────────────┬──────────────┬──────────────┐
      │search_catalog│list_datasets │ load_dataset │  run_python  │  make_chart  │ write_report │
      │ 목록 1,259종 │ 레지스트리    │ API→파일→샘플 │ 격리 실행    │ plotly       │ MD/HTML+코드 │
      └──────────────┴──────────────┴──────────────┴──────────────┴──────────────┴──────────────┘
                                   ▼
                 세션 상태(표·차트·코드 이력) → 답변 + 보고서 + 실행 기록(JSON)
```
- 판단·자율 수행 범위: 데이터 선택, 집계 방법, 차트 유형, 보고서 작성 여부는 모델이 정한다. 결과가 크게 갈리는 해석과 대량 수집은 사용자에게 확인한다. 수치 지어내기·샘플을 실제처럼 설명하기는 금지한다(시스템 프롬프트).
- 안전장치: 코드 실행 격리(허용 모듈·시간·메모리·파일 경로 제한), 도구 오류의 모델 자가 복구, 단계 상한, 서버측 fallbacks, 실행 기록 저장.

## 3. 주요 기능
1. 자연어 → 데이터 추천(동의어 사전·글자 바이그램 유사도·인기도)
2. 출처 자동 결정과 적재(Open API 페이지 수집·캐시, 파일 인코딩 판별, 합성 샘플 대체) + 구조 요약, 미등록 데이터는 `data/raw` 임의 파일 적재(`load_file`, 숫자·날짜 자동 추정)
3. 자율 분석(pandas) — 필터·결합·집계·파생변수, 오류 시 자동 수정
4. 시각화(11종) — 색각 이상 안전 팔레트, 이중 축 금지, 계열 8개 초과 시 '기타' 접기
5. 보고서 — 결론·근거·한계 + 출처/이용조건 표 + 실행 코드 + 재현 스크립트
6. 도민 친화 UI — 예시 질문, 분석 과정 펼쳐보기, 판단 과정 요약, 내려받기

**시나리오 점검에서 찾아 고친 문제 (2026-11-07)**
1. 유동인구 API 가 방화벽에 막힌 뒤 에이전트가 같은 API 를 다시 불렀다(시나리오 02). 이제 허브 오류를 종류별로 나눠, 질의 변수 오류일 때만 다시 시도하라고 안내한다.
2. API 고유 ID 가 없는 데이터(No.755)를 `source='api'` 로 다시 불러 실패했다(시나리오 05). 이제 자동 모드에서 API 를 건너뛴 이유를 결과에 적는다. 같은 질문을 다시 실행하니 6단계·27초가 4단계·24초로 줄었고 실패한 호출은 없었다.
3. 결론 한 문장이 품목별로 다른 결과를 하나로 묶어 잘못 요약했다(시나리오 04, 당근의 최저 월). 답을 내기 전에 결론의 순위와 증감이 근거 표와 맞는지 확인하는 규칙을 시스템 프롬프트에 넣었다.
4. (관찰) 4턴 대화를 보고서로 정리하는 턴은 157초가 걸렸다. 출력 1.26만 토큰의 대부분이 생각 과정이었다. 오류는 아니지만 앞으로 줄일 과제로 남긴다.
5. 공개 저장소 코드의 실행 결과로 실제 No.755 에는 내·외국인 구분이 없고, No.741 카드 데이터는 읍면동이 아닌 시군구·도심구분(동/읍면) 단위임을 확인했다. 시나리오 05 첫 질문을 '방문목적별 회복'으로 바꾸고, 합성 샘플과 레지스트리를 실제 구조에 맞췄다. 위 표의 05 결과는 바꾸기 전 질문과 샘플로 실행한 것이다.
6. 바뀐 구조로 다시 물어본 결과(클라우드, 샘플, effort medium):
   - 카드: '노형동만 따로 볼 수 없다'고 밝히고 제주시 동 지역 기준으로 답했다(3단계, 29초).
   - 입도객: 내·외국인 구분이 없다고 알리고 1~7월 같은 기간끼리 비교했다(4단계, 28초).
   - 관측소: 정류소마다 가장 가까운 관측소를 골라 평일·주말을 나눠 비교했다(7단계, 57초).
   - 정류소 지도: 정류소별 이용 자료(No.725)는 샘플뿐이고 정류소 위치(No.726)는 실제 API 라서, 둘을 섞으면 의미 없는 결과가 된다며 멈추고 실제 데이터로 가능한 노선별 분석(No.724)을 제안했다. 이 판단을 시스템 프롬프트 규칙으로 넣고, 시나리오 03 을 실데이터로 돌릴 수 있는 노선별 분석으로 바꿨다.

## 5. 검증 방법과 한계
- 자동 테스트(pytest, GitHub Actions 에서 Ubuntu 3.10/3.13·Windows 3.12 실행): 목록 검색, API 응답 파싱·페이지 수집·캐시, 컬럼 정규화, 샘플 적재, 임의 파일 적재(인코딩·제목 행·시트·형 추정·경로 제한), 샌드박스(차단·시간 초과·차트), 차트 생성, 에이전트 루프(정상·도구 오류·단계 상한).
- 재현성: 보고서에 실행 코드 전체와 재현 스크립트를 첨부, 턴별 실행 기록(JSON) 저장, 시나리오 파일로 동일 질문 재실행.
- 한계
  - LLM 의 비결정성: 같은 질문도 분석 경로가 달라질 수 있다(결과는 코드로 재검증 가능).
  - Open API 응답 필드명은 서비스마다 달라 `registry.yaml` 의 `rename` 보정이 필요할 수 있다(미보정 시 원본 컬럼명으로 동작).
  - 유동인구·카드 데이터는 추정치이며 기간이 서로 다르다(에이전트가 명시하도록 설계).
  - 외부 서비스 의존: Claude API(인터넷·과금), 제주데이터허브 Open API.

## 6. 센터 활용 방안
- 센터 PC 에 설치(`setup.bat` 한 번, 요구사양 충족, GPU 불필요)해 방문 도민이 직접 질문 → 보고서 출력.
- 센터 직원이 허브 데이터를 내려받아 `data/raw` 에 쌓아 두면 등록 작업 없이 그 자리에서 분석 가능(목록 1,259종 전체).
- 센터 보유 비공개 데이터는 `data/raw/` 에 두고 동일하게 분석(외부 반출 없음).
- 레지스트리(YAML)만 추가하면 새 데이터셋을 즉시 지원 → 센터 큐레이션 데이터 확대.
- 실행 기록(JSON)으로 "도민이 무엇을 묻는가"를 집계해 데이터 개방 우선순위에 활용.
